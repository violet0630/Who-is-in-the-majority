# 网络规则审计与改进方案

2026-11-21 · gxy

本文件只审查机制，不修改冻结基线。三个提议分别对应状态更新、阅读采样和单轮行动容量，必须分成独立实验条件。

## 1. 非观测节点的 p_hat

### 当前事实

`Simulation.step()` 只为有阅读内容的节点创建感知请求。主实验使用的 `ObserverSimulation._decide()` 对非观测节点把 `gamma`、`theta_d` 和 `theta_hd` 置零。非观测节点的 `perceived_support` 当前保持初始 0.5，但在当前行为公式里不参与它们的发言、评论或沉默概率。

因此这是一个状态语义缺口，尚不是当前 Q/J 结果的计算错误。把它改为观察者平均值会给非观测节点注入全网信号，改变的是模型机制。全局平均是一个信息上界条件，不应直接替换基线。

### 推荐方案

保留当前基线，增加三个离线可比较条件。

1. `carry-forward`。非观测节点保持自己的历史判断，继续关闭感知气候项。
2. `local-proxy`。非观测节点根据本轮可见消息和关注邻居的公开内容，使用去重作者的立场比例更新 p_hat。没有可见消息时沿用上一轮判断。
3. `observer-public-signal`。使用上一轮观察者平均 p_hat，并加入一个固定延迟。该条件回答公共信号是否会外溢。

全网观察者平均应作为第四个 `oracle-global-signal` 条件，只作敏感性上界。每个条件单独记录非观测节点 p_hat、行为概率和真实支持率。主结果继续只用观察者 Q/J，另报非观测节点公开行为变化。

## 2. 阅读上限

`read_feed()` 在窗口内从可见消息中无放回抽取 `min(read_limit, visible)` 条。当前主实验的 `read_limit=5`，所以当可见消息超过 5 条时，观察者只接触窗口的一小部分。

这会增加感知采样方差，也限制了上下文对重复作者和多评论的辨别。它不一定是错误，因为阅读上限本身是模型假设。更稳妥的变化是保留 5 作为历史基线，新增 8 和 11 两个条件，使用相同网络、随机流、发布记录和模型提示进行回放。

需同时记录每轮 `visible_count`、`read_count`、空阅读比例、独立作者数、输入 Token 和 Q/J。11 只有在大多数观察者实际可见消息不少于 11 时才有含义。若经常不足 11，它等价于“尽可能全读”，应使用不同的条件名。

## 3. 每轮多评论

当前 `Decision` 只有一个 `target_id`，`Simulation._prepare_messages()` 每个节点每轮最多生成一条消息，`make_message()` 只创建一个评论。多评论需要一起改变决策、消息、通知和统计。

Beta 分布本身是连续比例，不能直接当作评论条数。推荐使用带零值的 Beta-Binomial。

`comment_gate ~ Bernoulli(c)`

`comment_share ~ Beta(alpha, beta)`

`comment_count = 1 + Binomial(max_comments - 1, comment_share)`

`comment_gate=0` 时走原创或沉默。`max_comments` 建议先设为 3。每个评论目标从有效目标中无放回抽取，目标、文本、受众、通知和随机流都拥有独立事件键。评论数增加后的消息数量和 Token 成本必须单独记录。

第一阶段只做离线小图和固定发布记录回放。验证目标包括消息 ID 唯一、通知只计一次、同轮消息同步可见、评论目标不重复、空目标回退原创、每个节点的评论数分布和指标分母稳定。第二阶段再做真实模型试跑。

## 4. 合并路线

这些变化都会改变冻结协议和历史结果的可比性。它们应各自从 gxy 开出实验分支，先通过离线回放、固定随机流和成本审计，再进入真实 API。任何一个条件只有在主问题独立、结果可解释、审计可复现时才进入评审分支。当前不修改 `main`。
