# 网络根规则 v2 审计稿

状态：本地审计稿，未推送远程，未写入飞书。

## 目标

让每个节点拥有可解释的社区判断状态，让阅读抽样更接近现实信息流，让单轮评论数量呈现少数高活跃节点，同时保留可复现的轮次时序、随机流和成本审计。

历史实验协议继续作为 v1 基线。v2 只能使用新的协议、输入哈希、运行目录和结果报告。

## 一、统一的 p_hat 更新规则

### 状态含义

`p_hat` 表示节点在当前轮结束时对议题支持比例的判断。它在下一轮行为决策中生效。

### 观察节点

观察节点读取本轮消息后调用 LLM。LLM 返回的 `support` 写入下一轮状态。空阅读沿用上一轮判断，不发起请求。

### 非观察节点

非观察节点不调用 LLM。它们根据自己的本地阅读更新 `p_hat`。

1. 从本轮实际读到的消息中提取作者和公开立场。
2. 同一作者多条消息只计一次。
3. 使用去重作者的支持比例作为本轮本地估计。
4. 没有可用作者时沿用上一轮 `p_hat`。
5. 本轮估计只影响下一轮决策。

评论引用的原帖只用于理解上下文，不作为第二条独立观察。

### 行为影响

非观察节点不再把 `gamma`、`theta_d` 和 `theta_hd` 强制置零。它们使用本地 `p_hat` 参与反馈气候项、私人立场与感知气候的交互项，以及发言、评论、原创和沉默概率。

观察节点继续使用 LLM 感知。两类节点的感知来源不同，但状态变量语义一致。

### 全局平均的边界

观察节点平均 `p_hat` 不作为主规则输入非观察节点。它只能作为单独的上界条件。

- `local_proxy` 作为主规则
- `delayed_public_signal` 使用上一轮观察节点平均值并加入一轮延迟
- `global_oracle` 使用当前全局平均，只用于敏感性上界

三种来源不得混写到同一个正式结果中。

## 二、阅读规则

### 新默认

- `window=2`
- `read_limit=11`
- 可见消息少于 11 条时全部读取
- 可见消息超过 11 条时无放回抽样
- 采样使用节点、轮次和用途独立的随机流

### 必须记录的字段

每个节点每轮记录 `visible_count`、`read_count`、`unique_author_count`、`empty_reading`、`carried_forward` 和输入 Token 数。

历史 `read_limit=5` 作为 v1 基线。`read_limit=8` 只用于迁移检查，不与 v2 主结果混合。

### 验收条件

- 读到的消息都来自当前窗口和节点受众
- 不重复抽取消息
- 空阅读不调用 LLM
- 读数不足 11 时不会伪造 11 条
- 同一随机种子可复现阅读集合
- 观测到的 Token 增长单独报告

## 三、多评论规则

### 决策分层

每个节点每轮依次决定是否发言、发言类型是原创还是评论、评论数量、每条评论的目标、每条评论的赞同或反对方向、每条评论的文本和受众。

### 评论数量

保持现有 `comment_gate` 作为是否评论的门控。通过门控后使用 `share ~ Beta(1, 9)`，`count = 1 + Binomial(max_comments - 1, share)`，`max_comments = 3`。

当可评论目标少于抽样数量时，评论数量截断为有效目标数。目标数为零时回退原创。该规则让绝大多数评论节点发送一条评论，少数节点发送两到三条。评论数量分布必须写入协议。

### 目标和消息

- 目标从有效目标中无放回抽取
- 每条评论使用独立随机事件键
- 消息 ID 包含节点、轮次和评论槽位
- 每条评论独立产生受众
- 每条评论独立触发目标作者通知
- 同一轮所有消息仍然统一发布

### 新指标

记录 `comments_per_node`、`comments_per_round`、`unique_comment_authors`、`notification_count`、`comment_target_reuse` 和 `message_count`。

原有 `public_support`、`opponent_silence` 和 `public_conformity` 保持定义。沉默表示本轮没有任何公开消息，不表示没有评论。

## 四、迁移顺序

1. 先实现状态更新，不改阅读上限和评论数量。
2. 用固定发布记录回放，验证非观察节点 `p_hat` 和行为概率。
3. 将阅读上限从 5 改为 11，检查采样、Token 和 Q/J。
4. 实现多评论，先用无 LLM 小图验证消息、通知和指标。
5. 固定 v2 协议、输入哈希、运行器哈希和结果目录。
6. 先运行技术试跑，再决定完整 API 批次。

## 五、禁止事项

- 不覆盖 v1 结果
- 不把全局观察者平均值混入本地估计
- 不把评论数量变化解释为观点比例变化
- 不把消息条数当作独立作者数
- 不把 5、8、11 三种阅读上限混入同一主结果
- 不在完成审计前合并到 `main`
